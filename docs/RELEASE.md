# Выпуск и обслуживание

**Кандидат 0.11.0.** Документ описывает эксплуатационный контракт и критерии приёмки, а не подтверждает прохождение всех проверок. Установка и первый запуск — в [README](../README.md); потоки данных — в [PRIVACY](PRIVACY.md).

## Что запускается

- Chrome загружает распакованное расширение из постоянной папки проекта. Docker запускает только HTTP-сервер для субтитров YouTube и CPU-распознавания.
- `docker compose up -d --build` собирает локальный образ `subsanywhere-server:0.11.0` и запускает сервис `subtitles`. Это не загрузка готового опубликованного образа.
- `compose.yaml` публикует `127.0.0.1:43817`, без доступа из локальной сети. Внутри контейнера сервер слушает `0.0.0.0:43817`; не переносите эту настройку на хост и не открывайте порт наружу.
- Сервер работает от UID/GID `10001:10001`, с read-only корневой ФС, временным `/tmp`, без Linux capabilities и с постоянными томами. CPU-образ включает Python 3.11, FFmpeg, FunASR, PyTorch и pypinyin. Python-зависимости в `local-server/uv.lock` сохранены без изменений; загрузчик больше не использует yt-dlp и Node.js.
- Модели импортируются отдельно из существующего кэша командой из README. Инструмент `model-import` работает без сети, не перезаписывает имеющиеся модели. Веса не входят в образ.

Не меняйте имя Compose-проекта без намеренного переноса данных: `name: subsanywhere` определяет имена томов. Примеры ниже предполагают стандартное имя и порт. На текущем Mac используется [нативный LaunchAgent](LOCAL-DEVELOPMENT.md), не Docker.

## Диагностика и жизненный цикл

Все команды выполняются из папки проекта; блоки `text` подходят и для macOS/Linux, и для PowerShell.

```text
docker compose ps
docker compose logs --tail 100 subtitles
docker compose exec subtitles python healthcheck.py
```

Откройте `http://127.0.0.1:43817/health` в браузере. Проверка контейнера ожидает `ok: true`, `service: "subsanywhere"`, `api_version: 1`. Сведения `checks` и `capabilities` отделяют наличие компонентов от доступности API. Отсутствие ASR-моделей не должно делать сам API `unhealthy`; готовность зависимостей не подтверждает загрузку конкретного ролика или качество ASR.

| Действие | Команда | Данные и задания |
|---|---|---|
| Запуск после остановки | `docker compose up -d` | Использует прежние тома |
| Перезапуск процесса | `docker compose restart subtitles` | Незавершённое распознавание прерывается, повтор — вручную |
| Остановка | `docker compose stop subtitles` | Контейнер и тома сохраняются |
| Удалить контейнер и сеть | `docker compose down` | Именованные тома сохраняются; для обычной остановки достаточно `stop` |
| Пересобрать после обновления | `docker compose up -d --build` | Использует прежние тома, может прервать активное задание |

**Не используйте `docker compose down -v`, `docker volume prune` или сброс данных Docker Desktop для обновления/исправления ошибки.** Это может удалить модели и результаты. Автоперезапуск `unless-stopped` не запускает вручную остановленный сервис и не заменяет запуск Docker Desktop.

Перед обновлением дождитесь завершения задания, сохраните резервную копию и обновите исходники выпуска в прежней папке, не затирая собственные изменения. Пересоберите сервер, проверьте health, нажмите **Reload** у расширения в `chrome://extensions` и обновите страницы с видео. Не удаляйте расширение: его данные не входят в Docker-тома. Откат на более старую схему хранилища не гарантирован; нужны совместимая версия и предварительная копия профиля Chrome.

## Video Download API

Субтитры и аудио YouTube загружаются только через внешний API, без yt-dlp/cookies fallback. Compose передаёт серверу `SUBSANYWHERE_VIDEO_API_KEY` из окружения хоста (пустой по умолчанию) и `SUBSANYWHERE_VIDEO_API_URL` (по умолчанию `https://p.savenow.to`). Ключ не помещается в образ, исходники или Chrome. Нативный вариант с приватным файлом описан в [LOCAL-DEVELOPMENT](LOCAL-DEVELOPMENT.md#video-download-api).

Загрузка запускается явно кнопкой **«Скачать»** после выбора `en`/`zh`; открытие окна и смена языка не создают платное задание. Китайские субтитры запрашиваются как `zh-Hans`, аудио — `zh-CN`. При отсутствии выбранной звуковой дорожки провайдер может молча вернуть основную, поэтому язык аудио не гарантирован. Пиньинь и ASR остаются локальными.

Принятие задания в очередь уже может тарифицироваться. Сервер сохраняет внешний ID и после таймаута опрашивает то же задание без повторной отправки; сначала восстановите статус, не создавайте дубликат. Старые SRT остаются, новые результаты и дорожки разделены по языку.

**Исторический архив cookies:** `compose.cookies.yaml`, `cookie-import` и объявление тома `subsanywhere_cookies` сохранены без удаления данных. Это не настройка нового загрузчика: сервер больше не монтирует cookie-том и не читает профиль Chrome. Старые экспорты и резервные копии по-прежнему являются чувствительными данными сессии.

## Где находятся данные

| Данные | Docker | Нативный сервер / Chrome |
|---|---|---|
| SRT, аудио, TXT, Markdown, состояние заданий | Том `subsanywhere_subtitles`, каталог `/data/subtitles/<video-id>/` | По умолчанию `$HOME/Downloads/SubsAnywhere/<video-id>/`; на текущем Mac — путь из [LOCAL-DEVELOPMENT](LOCAL-DEVELOPMENT.md#данные-и-резервная-копия) |
| SenseVoiceSmall и FSMN VAD | Том `subsanywhere_models`, `/models`, read-only для сервера | Существующий кэш `iic` либо `SUBSANYWHERE_MODELS_DIR` |
| Выбор плеера, оформление, SRT и кэш встроенных дорожек | **Не в Docker** | `chrome.storage.local` текущего профиля расширения, отдельно для каждой страницы |
| API-ключи и модели DeepSeek/OpenAI | **Не в Docker** | Локальное хранилище расширения, общие для страниц; активен один сервис перевода |
| Ключ Video Download API | Переменная окружения сервера, не в томах данных/моделей | Приватный файл или переменная сервера, не хранилище Chrome |
| Архив cookies | Прежний том `subsanywhere_cookies`, больше не подключён к серверу | Старый экспорт на хосте сохраняется отдельно |

Docker не создаёт автоматически папку результатов в «Загрузках» хоста. Чтобы забрать файлы работающего сервера, сначала дождитесь завершения записи, затем выполните:

```text
docker compose cp subtitles:/data/subtitles ./SubsAnywhere-export
```

Старые файлы `youtube-<video-id>-youtube.srt`, аудио и `generated.*` сохраняются. Новые файлы разделены по языку; служебное состояние включает ID задания провайдера. Серверные результаты и сохранённая в Chrome копия SRT независимы; удаление одной копии не удаляет другую.

## Резервная копия и восстановление

Описанная ниже копия двух томов данных/моделей не включает профиль Chrome, исходники, API-ключ, внешний файл cookies **и отдельный том `subsanywhere_cookies`**. Полный снимок Docker/архив всех томов, напротив, может содержать импортированные cookies; защищайте его как данные сессии. Сохраните исходные SRT отдельно. Встроенного экспорта/восстановления всех настроек расширения пока нет: для полного переноса требуется отдельная резервная копия профиля Chrome при закрытом браузере. Не считайте Chrome Sync резервной копией этого локального хранилища.

### Копирование обоих томов

Дождитесь завершения заданий и выполните `docker compose stop subtitles`. Проверьте исходные тома командой `docker volume inspect subsanywhere_subtitles subsanywhere_models`: если какой-либо том не найден, остановитесь и уточните имя проекта, иначе можно получить пустую копию. Создайте каталог `backup` в папке проекта:

```bash
# macOS / Linux
mkdir -p backup
```

```powershell
# Windows PowerShell
New-Item -ItemType Directory -Force -Path backup | Out-Null
```

Далее одна команда одинакова для обеих оболочек. `${PWD}` — текущая папка проекта. Если архив с таким именем уже существует, сначала переместите его: следующая команда его заменит.

```text
docker run --rm --network none --read-only --user 0:0 --mount type=volume,src=subsanywhere_subtitles,dst=/data,readonly --mount type=volume,src=subsanywhere_models,dst=/models,readonly --mount "type=bind,src=${PWD}/backup,dst=/backup" --entrypoint tar subsanywhere-server:0.11.0 -czf /backup/subsanywhere-data-models.tgz -C / data models
```

Служебный контейнер работает как root для чтения/сохранения владельцев файлов; основной сервер остаётся непривилегированным. Исходные тома смонтированы только для чтения, сеть выключена. Архив содержит чувствительные тексты и историю видео; ограничьте к нему доступ средствами своей ОС. На Linux владельцем архива будет root. Здесь намеренно нет перенаправления двоичного потока через PowerShell.

Проверьте, что архив читается, и снова запустите сервер:

```text
docker run --rm --network none --read-only --user 0:0 --mount "type=bind,src=${PWD}/backup,dst=/backup,readonly" --entrypoint tar subsanywhere-server:0.11.0 -tzf /backup/subsanywhere-data-models.tgz
docker compose up -d
```

Проверка списка файлов не заменяет пробного восстановления.

### Восстановление без перезаписи действующих томов

Используйте доверенный собственный архив и совместимый образ. Остановите текущий сервер. Пример восстанавливает данные в **другой Compose-проект** `subsanywhere-restore`, оставляя исходные тома нетронутыми. Если это имя уже использовалось, выберите другое во всех командах; проверка ниже откажет для непустых целевых томов.

```text
docker compose stop subtitles
docker run --rm --network none --read-only --user 0:0 --mount type=volume,src=subsanywhere-restore_subtitles,dst=/data,volume-nocopy --mount type=volume,src=subsanywhere-restore_models,dst=/models,volume-nocopy --mount "type=bind,src=${PWD}/backup,dst=/backup,readonly" --entrypoint python subsanywhere-server:0.11.0 -c "from pathlib import Path; import subprocess; assert all(not any(Path(p).iterdir()) for p in ['/data', '/models']), 'Target volumes must be empty'; subprocess.run(['tar', '-xzf', '/backup/subsanywhere-data-models.tgz', '-C', '/'], check=True)"
```

`volume-nocopy` оставляет новые целевые тома пустыми до распаковки. **При ненулевом коде выхода остановитесь:** не запускайте сервер на неполном восстановлении. При успехе:

```text
docker compose -p subsanywhere-restore up -d
docker compose -p subsanywhere-restore exec subtitles python healthcheck.py
docker compose -p subsanywhere-restore ps
```

Для новых загрузок отдельно настройте ключ Video Download API; он и архивный cookie-том не входят в эту копию. Проверьте готовый SRT и модели, затем откройте расширение. Для последующего обслуживания восстановленного экземпляра сохраняйте `-p subsanywhere-restore`, иначе команды обратятся к исходным томам. Для возврата остановите восстановленный экземпляр и выполните обычный `docker compose up -d`; не запускайте оба на одном порту.

## Если что-то не работает

| Симптом | Что проверить / сделать |
|---|---|
| Docker daemon недоступен | Запустить Docker Desktop/Engine, проверить `docker compose version`; на Windows нужен режим Linux-контейнеров |
| `port is already allocated` | На 43817 уже есть сервер. Не завершать чужие процессы вслепую; штатно остановить прежний экземпляр. Изменение порта Compose не меняет адрес расширения |
| API отвечает, но ASR недоступен | Проверить `checks`/`capabilities` в `/health`, полный набор моделей, успешный импорт и перезапуск. `model-import` ничего не скачивает |
| `Incomplete cached model` / `Model already exists` | Указан не каталог `iic`, неполный кэш либо повторный импорт. Исправить источник; не очищать том для обычного обновления |
| Docker не видит файл/каталог хоста | Абсолютный путь должен существовать и быть доступен Docker Desktop. Не смешивать пути WSL и PowerShell; строки с пробелами заключать в кавычки |
| Сервер не отвечает / timeout | Проверить `ps`, health и логи, затем повторить проверку в расширении. Timeout клиента не означает отмену задания; не запускать несколько генераций подряд |
| API отклоняет запрос / 403 / 429 / дорожка отсутствует | Проверить серверный ключ, баланс, адрес провайдера, доступность видео и язык (`zh-Hans` для китайских субтитров); выждать при ограничении частоты. Cookies и yt-dlp не используются как запасной путь |
| Сервер занят | По умолчанию один слот тяжёлой работы; дождаться завершения и повторить. Безлимитной очереди заданий нет |
| Задание прервано после перезапуска | Повторить создание вручную. Предыдущий SRT сохраняется; автоматического возобновления ASR с места остановки нет |
| `unhealthy`, контейнер завершился, OOM, нет места | Проверить логи, ресурсы Docker и свободный диск. Сохранить результаты перед очисткой; не удалять тома. Health сам по себе не измеряет запас памяти |
| Плеер не найден / выбранная дорожка временно пропала | Запустить видео, нажать подключение/повторный поиск, проверить разрешение на iframe. Не очищать сохранённую дорожку. `chrome://` и другие служебные страницы не поддерживаются |
| Настройки не сохранились | Проверить сообщение сохранения в popup, повторить сохранение/загрузку. Не переустанавливать расширение как первый способ исправления |
| Перевод отсутствует | Проверить выбранный сервис, его ключ и модель, сеть и состояние аккаунта DeepSeek/OpenAI. Сервер Docker для перевода не нужен; отсутствие перевода не должно удалять SRT |

## Бюджет CPU и памяти

Для расчёта на **этом компьютере** нужен Python 3.10+ без дополнительных пакетов. Скрипт не запускает Docker, контейнеры или ASR, не перезапускает сервер и не прерывает задания. Сначала просмотрите результат:

```text
python3 scripts/configure-resources.py --dry-run
```

В PowerShell используйте `py -3` вместо `python3`. Для записи выполните `python3 scripts/configure-resources.py`; по умолчанию создаётся/атомарно заменяется **gitignored** `compose.resources.local.yaml` в корне проекта. YAML также выводится в stdout, диагностика — в stderr. `--percent 25` выбирает четверть CPU/RAM; значение по умолчанию — `100/3` процента, допустимо `0 < percent <= 100`. `--output <путь>` меняет файл назначения (родительский каталог должен существовать; произвольный путь не обязательно исключён из Git). `--dry-run` ничего не записывает, даже если файл уже существует. При неудачном определении CPU/RAM скрипт завершается с ошибкой, не подставляет выдуманный размер компьютера.

Расчёт: **минимум из одной трети физических ресурсов хоста и доступных ограничений ОС/Docker VM**, отдельно для CPU и RAM. Скрипт должен работать на хосте, не внутри контейнера или WSL, если требуется доля физического Windows-компьютера. На macOS используется `sysctl hw.memsize`, на Linux — `/proc/meminfo`, на Windows — `GlobalMemoryStatusEx`; CPU — логические процессоры. Linux дополнительно учитывает affinity, доступные cgroups v1/v2, квоты CPU, cpuset, лимиты памяти и видимые родительские группы. Ресурсы внешнего гипервизора из гостевой ОС и скрытые предки cgroup не определяются. На macOS/Windows определяется физическая ёмкость ОС; отдельные ограничения `rlimit` / Windows Job Objects не обнаруживаются.

Для локального Docker context скрипт только читает `docker context inspect` / `docker info` (каждая команда с таймаутом). `NCPU` / `MemTotal` ограничивают рассчитанный бюджет ресурсами Engine/VM, **не делятся повторно на три**. Удалённые contexts отклоняются. Если Docker выключен/недоступен, выводится предупреждение: VM не измерена, результат ограничен только хостом/ОС. Перед применением повторите расчёт с доступным Docker; скрипт сам его не включит. Настройки Docker Desktop и ресурсы компьютера могут измениться — файл является снимком, а не автоматической перенастройкой при каждом запуске.

Например, для хоста с 14 логическими CPU и 24 ГиБ RAM бюджет — `4.666666` CPU (округление вниз при записи) и `8589934592` байта (8 ГиБ), 4 вычислительных потока. Если Docker VM имеет только 6 ГиБ, память контейнера ограничивается 6 ГиБ, а не 2 ГиБ. Число потоков — `max(1, floor(cpu_quota))`; на одноядерном компьютере один поток **не равен** квоте в треть CPU.

Созданный файл **не применяется автоматически**. Проверить итоговую конфигурацию без запуска:

```text
docker compose -f compose.yaml -f compose.resources.local.yaml config
```

Когда задания завершены и оператор сам решит применить изменения, используйте `docker compose -f compose.yaml -f compose.resources.local.yaml up -d --build`. Сохраняйте этот набор `-f` во всех последующих `up`/обновлениях: обычная команда без overlay вернёт фиксированный fallback из `compose.yaml` — **4 CPU / 8 ГиБ**, это не автоматическая треть ресурсов произвольного компьютера. `restart` сам по себе не применяет новые лимиты.

Docker получает `cpus`, `mem_limit` и **равный ему `memswap_limit`**, отключающий swap контейнера. Эти лимиты охватывают весь сервис и его дочерние процессы, включая ASR, HTTP-сервер, FFmpeg и tmpfs; они не ограничивают весь Docker Desktop, сборку образа или отдельный импорт моделей. CPU — квота времени планировщика, не обещание мгновенно ровной загрузки; RAM — жёсткий контейнерный предел при поддержке ограничений хостом. Его превышение может вызвать OOM/завершение процесса, а не просто замедлить распознавание. Модель может не помещаться на маленьком компьютере: бюджет не является заявлением о минимальной конфигурации или качестве. Скрипт отказывает ниже 0.01 CPU / 6 МиБ, но даже больший бюджет не гарантирует запуск ASR. Swap контейнера отключён, однако это не запрещает хосту выгружать память самой VM.

**Нативный запуск:** `get_resource_budget()` из `local-server/resource_budget.py` по умолчанию возвращает треть CPU/RAM, доступных процессу. `SUBSANYWHERE_RESOURCE_FRACTION` позволяет явно задать долю `0 < fraction <= 1`. В базовом Compose и overlay она равна `1`: cgroup уже содержит готовый бюджет, повторного деления нет. Модуль только рассчитывает `cpu_quota`, `memory_bytes`, `threads`, `fraction`; для нативного ASR эти значения используются интеграцией сервера/worker. Ограничение потоков Torch/OMP/MKL и периодическая проверка RSS являются **мягкими защитными мерами**, не переносимой жёсткой квотой CPU/RAM: возможны кратковременные превышения между проверками, дополнительные потоки и память дочерних процессов. Для жёсткого общего лимита используйте Docker/ограничения ОС; не выдавайте RSS-watchdog или число потоков за такую гарантию.

## Нативный запуск для разработчика

`npm run local-server` остаётся необязательным вариантом. Зависимости на хосте настраиваются отдельно: Python, FFmpeg, pypinyin и окружение FunASR. Docker-команда не устанавливает их на хост. Укажите `SUBSANYWHERE_ASR_PYTHON` и `SUBSANYWHERE_MODELS_DIR`; для уже настроенного текущего Mac следуйте [LOCAL-DEVELOPMENT](LOCAL-DEVELOPMENT.md), не запускайте второй процесс рядом с LaunchAgent.

Для прямого запуска используйте `python3 local-server/server.py` на macOS/Linux или `py -3 local-server/server.py` в PowerShell с подготовленным окружением. Переменные задаются через `export NAME="..."` либо `$env:NAME = '...'`. Настраиваемые пути — `SUBSANYWHERE_OUTPUT_DIR`, `SUBSANYWHERE_ASR_PYTHON`, `SUBSANYWHERE_MODELS_DIR`; адрес по умолчанию — `127.0.0.1:43817`.

Для загрузок задайте `SUBSANYWHERE_VIDEO_API_KEY` либо `SUBSANYWHERE_VIDEO_API_KEY_FILE`; стандартный приватный путь — `~/Library/Application Support/SubsAnywhere/video-api-key`. Cookies Chrome не читаются. Переносимость самостоятельно собранного нативного ASR-окружения не подтверждается наличием Dockerfile.

## Матрица приёмки

Статусы относятся к **конкретному кандидату 0.11.0**, а не ко всем платформам. Код, unit-тест или `healthy` не являются доказательством сценария на реальном сайте. Перед публикацией приложите к каждому выполненному пункту версию/commit, ОС и архитектуру, команды, результат и при необходимости обезличенный снимок экрана. Платные API-запросы и сетевые загрузки выполняются только с отдельного согласия.

**Подтверждён ограниченный офлайн-прогон:** собранный Linux ARM64 Docker-образ выполнил реальное CPU-распознавание с кэшированными моделями и `--network none`. Вход `SenseVoiceSmall/example/zh.mp3`, длительность `5.616` секунды; получен SRT с одним сегментом `00:00:00,420–00:00:05,450`, TXT и Markdown непустые. Это подтверждает запуск моделей на коротком образце, но не весь путь загрузки YouTube, длительные задания, Windows или amd64.

Также выполнен офлайн-импорт существующего кэша инструментом `model-import` в стандартный том `subsanywhere_models`; проверены файлы весов размером `936291369` и `1721366` байт. Нативный каталог «Загрузки» не изменялся. Переключение основного порта с уже работающего нативного сервера на Docker этим не подтверждается и не выполняется автоматически.

В `.github/workflows/release-checks.yml` добавлены unit/syntax- и браузерные проверки на Linux/macOS, а также сборка и Docker-smoke на Linux/amd64. **Удалённый CI ещё не подтверждён.** Локальные команды: `npm test`, `npm run check`, `npm run test:browser`; после сборки образа — `npm run test:docker`. Браузерные фикстуры не заменяют реальные YouTube/iframe/fullscreen-проверки.
