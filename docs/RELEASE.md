# Выпуск и обслуживание

**Кандидат 0.11.0.** Это эксплуатационный контракт и список проверок, а не отчёт об их прохождении. Установка — в [README](../README.md), потоки данных — в [PRIVACY](PRIVACY.md).

## Что запускается

- Chrome загружает распакованное расширение из постоянной папки проекта. Docker запускает только HTTP-сервер загрузки готовых субтитров YouTube через Video Download API и локального пиньиня.
- `docker compose up -d --build --wait` собирает локальный образ `subsanywhere-server:0.11.0` и запускает сервис `subtitles`; это не загрузка опубликованного готового образа. `npm run docker:up` выполняет ту же команду.
- `compose.yaml` публикует `127.0.0.1:43817`; внутри контейнера сервер слушает `0.0.0.0:43817`. Не открывайте порт в LAN/интернет.
- Python 3.11, единственная Python-зависимость — `pypinyin`. Образ не содержит FFmpeg, Torch, моделей распознавания или cookies. Распознавание, загрузка аудио, импорт моделей/cookies и активная база словаря удалены.
- Сервер работает от UID/GID `10001:10001`, с read-only корневой ФС, временным `/tmp`, без Linux capabilities. Единственный постоянный том — `subsanywhere_subtitles`, смонтированный в `/data`.
- Фиксированные лимиты Compose: **1 CPU / 512 MiB**, `memswap_limit: 512m`. Автоматического расчёта бюджета и resource overlay больше нет. Это настройки, не подтверждение испытаний или достаточности памяти на каждой платформе.

Не меняйте имя Compose-проекта без намеренного переноса: `name: subsanywhere` определяет имя тома. На текущем Mac используется [нативный LaunchAgent](LOCAL-DEVELOPMENT.md); второй сервер на том же порту запускать нельзя.

## Диагностика и жизненный цикл

Команды выполняются из папки проекта:

```text
docker compose ps
docker compose logs --tail 100 subtitles
docker compose exec subtitles python healthcheck.py
```

Откройте `http://127.0.0.1:43817/health`. Ожидаются `ok: true`, `service: "subsanywhere"`, `api_version: 1`; `checks` и `capabilities` описывают ключ Video Download API и локальный пиньинь. Health не подтверждает загрузку конкретного видео.

| Действие | Команда |
|---|---|
| Запуск после остановки | `docker compose up -d --wait` |
| Перезапуск процесса | `docker compose restart subtitles` |
| Остановка с сохранением контейнера и тома | `docker compose stop subtitles` |
| Удаление контейнера и сети с сохранением тома | `docker compose down` |
| Пересборка после обновления | `docker compose up -d --build --wait` |

**Не используйте `docker compose down -v`, `docker volume prune` или сброс Docker Desktop для обновления/исправления ошибки.** Можно потерять результаты и исторические данные. `unless-stopped` не запускает вручную остановленный сервис и не заменяет запуск Docker Desktop.

Перед обновлением дождитесь завершения записи, сделайте резервную копию и обновите исходники в прежней папке, сохранив свои изменения. Пересоберите сервер, проверьте health, нажмите **Reload** в `chrome://extensions` и обновите страницы с видео. Не переустанавливайте расширение: его данные не входят в Docker-том. Откат требует совместимой версии и отдельной копии профиля Chrome.

## Video Download API

Только готовые субтитры YouTube, без загрузки аудио, распознавания, yt-dlp или cookies fallback. Compose передаёт `SUBSANYWHERE_VIDEO_API_KEY` из окружения хоста и `SUBSANYWHERE_VIDEO_API_URL` (по умолчанию `https://p.savenow.to`). Ключ не включается в образ, исходники или расширение. [Нативная настройка](LOCAL-DEVELOPMENT.md#video-download-api).

Загрузка запускается кнопкой **«Скачать»** после выбора `en`/`zh`; китайский запрос использует `zh-Hans`. Открытие окна и смена языка не создают новое платное задание. Оплата возможна уже при принятии в очередь. Сервер сохраняет ID задания и после таймаута/перезапуска проверяет прежнее задание без повторной отправки: сначала восстановите статус, не создавайте дубликат. Новые результаты разделены по языку. Пиньинь вычисляется локально, произношение выполняет браузерный TTS расширения.

## Где находятся данные

| Данные | Место |
|---|---|
| SRT и состояние заданий, включая ID провайдера | Том `subsanywhere_subtitles`, `/data/subtitles/<video-id>/`; нативно — `SUBSANYWHERE_OUTPUT_DIR`, по умолчанию `~/Downloads/SubsAnywhere` |
| Текущая нативная рабочая папка на Mac | [LOCAL-DEVELOPMENT](LOCAL-DEVELOPMENT.md#данные-и-резервная-копия) |
| Выбор плеера, оформление, SRT, кэш дорожек, настройки TTS | `chrome.storage.local`, не Docker |
| Ключи и выбранные модели DeepSeek/OpenAI | Локальное хранилище расширения, не Docker |
| Ключ Video Download API | Окружение/приватный файл сервера, не том данных и не Chrome |

Старые аудиофайлы, результаты распознавания, кэши моделей, `words.sqlite3` и прежние тома моделей/cookies сохраняются как **неиспользуемые архивы**. Поддержки их импорта, распознавания или активного словаря в коде нет. В текущий Compose старые тома не подключены. Архивы cookies и базы могут содержать чувствительные данные.

Docker не создаёт папку результатов в «Загрузках» хоста. После завершения записи можно экспортировать субтитры:

```text
docker compose cp subtitles:/data/subtitles ./SubsAnywhere-export
```

Копия SRT в Chrome и серверный файл независимы: удаление одной не удаляет другую.

## Резервная копия и восстановление

Ниже копируется **только текущий том `subsanywhere_subtitles` целиком**. Он может содержать и исторические файлы, включая `words.sqlite3`: резервирование не означает их использование сервером. Копия не включает профиль Chrome, исходники, API-ключ, нативные каталоги или отдельные старые тома моделей/cookies. Для настроек расширения нужна отдельная копия профиля Chrome при закрытом браузере; Chrome Sync её не заменяет.

### Копирование текущего тома

Дождитесь завершения записи, остановите сервер и проверьте имя исходного тома. Если `inspect` не находит его, остановитесь и уточните имя проекта, иначе можно получить пустую копию.

```text
docker compose stop subtitles
docker volume inspect subsanywhere_subtitles
```

Создайте каталог `backup` в папке проекта:

```bash
# macOS / Linux
mkdir -p backup
```

```powershell
# Windows PowerShell
New-Item -ItemType Directory -Force -Path backup | Out-Null
```

Следующие команды одинаковы для обеих оболочек; `${PWD}` — папка проекта. Переместите существующий архив с таким именем: команда его заменит.

```text
docker run --rm --network none --read-only --user 0:0 --mount type=volume,src=subsanywhere_subtitles,dst=/data,readonly --mount "type=bind,src=${PWD}/backup,dst=/backup" --entrypoint tar subsanywhere-server:0.11.0 -czf /backup/subsanywhere-data.tgz -C / data
docker run --rm --network none --read-only --user 0:0 --mount "type=bind,src=${PWD}/backup,dst=/backup,readonly" --entrypoint tar subsanywhere-server:0.11.0 -tzf /backup/subsanywhere-data.tgz
docker compose up -d --wait
```

Служебный контейнер использует root для сохранения владельцев файлов; основной сервер остаётся непривилегированным. Исходный том доступен только для чтения, сеть отключена. На Linux архив принадлежит root. Ограничьте доступ к архиву: он содержит тексты и историю видео, иногда исторические личные данные. Перенаправление двоичного потока через PowerShell не требуется. Список файлов не заменяет пробного восстановления.

### Восстановление без перезаписи действующего тома

Используйте доверенный собственный архив и совместимый образ. Пример создаёт **другой Compose-проект** `subsanywhere-restore`, не изменяя исходный том. Если это имя уже использовалось, выберите новое во всех командах. Проверка откажет для непустого целевого тома.

```text
docker compose stop subtitles
docker run --rm --network none --read-only --user 0:0 --mount type=volume,src=subsanywhere-restore_subtitles,dst=/data,volume-nocopy --mount "type=bind,src=${PWD}/backup,dst=/backup,readonly" --entrypoint python subsanywhere-server:0.11.0 -c "from pathlib import Path; import subprocess; assert not any(Path('/data').iterdir()), 'Target volume must be empty'; subprocess.run(['tar', '-xzf', '/backup/subsanywhere-data.tgz', '-C', '/'], check=True)"
```

`volume-nocopy` оставляет новый том пустым до распаковки. **При ненулевом коде выхода остановитесь:** не запускайте сервер на неполном восстановлении. При успехе:

```text
docker compose -p subsanywhere-restore up -d --wait
docker compose -p subsanywhere-restore exec subtitles python healthcheck.py
docker compose -p subsanywhere-restore ps
```

Отдельно настройте ключ Video Download API и проверьте готовый SRT в расширении. Для обслуживания восстановленного экземпляра сохраняйте `-p subsanywhere-restore`. Для возврата остановите его и выполните обычный `docker compose up -d --wait`; не запускайте оба на одном порту.

## Если что-то не работает

| Симптом | Что проверить / сделать |
|---|---|
| Docker daemon недоступен | Запустить Docker Desktop/Engine; на Windows нужен режим Linux-контейнеров |
| Порт 43817 занят | Штатно остановить прежний экземпляр; не завершать чужие процессы вслепую. Смена порта Compose не меняет адрес расширения |
| Сервер не отвечает / timeout | Проверить `ps`, health и логи. Таймаут не отменяет платное задание; сначала восстановить его статус |
| API отклоняет запрос / 403 / 429 / дорожка отсутствует | Проверить ключ, баланс, адрес провайдера, доступность видео и язык; выждать при ограничении частоты. Аудио/ASR/cookies fallback нет |
| `unhealthy`, OOM, нет места | Проверить логи, лимиты Docker и свободный диск; сохранить данные перед очисткой, не удалять тома |
| Плеер/дорожка не найдены | Запустить видео, повторить поиск, проверить разрешение на iframe; не очищать сохранённую дорожку. Служебные страницы Chrome не поддерживаются |
| Настройки не сохранились | Проверить сообщение сохранения; не переустанавливать расширение как первый способ исправления |
| Перевод отсутствует | Проверить сервис DeepSeek/OpenAI, ключ, модель и сеть. Docker для перевода не нужен |

## Нативный запуск для разработчика

`npm run local-server` — необязательный вариант. Нужен Python 3.11 и `pypinyin` версии из `local-server/pyproject.toml`; Docker не устанавливает зависимости на хост. Запуск напрямую: `python3 local-server/server.py` (macOS/Linux) или `py -3 local-server/server.py` (PowerShell). Адрес по умолчанию — `127.0.0.1:43817`, каталог — `SUBSANYWHERE_OUTPUT_DIR`.

Ключ загрузок: `SUBSANYWHERE_VIDEO_API_KEY` либо `SUBSANYWHERE_VIDEO_API_KEY_FILE`; стандартный приватный файл — `~/Library/Application Support/SubsAnywhere/video-api-key`. Настройки ASR, моделей и автоматического бюджета удалены. Для текущего Mac следуйте [LOCAL-DEVELOPMENT](LOCAL-DEVELOPMENT.md), не запускайте второй процесс рядом с LaunchAgent.

## Матрица приёмки

После удаления распознавания прошли `npm run check` и 38 серверных тестов (`python3 -m unittest discover -s local-server/tests`). Исторические проверки прежнего ASR/импорта не подтверждают нынешнюю поставку. Сборка Docker, браузерные проверки и перезапуск сервиса в этом обновлении не выполнялись; лимиты 1 CPU / 512 MiB не объявляются проверенными.

| Проверка | Критерий |
|---|---|
| Версии и упаковка | Согласованные версии, загрузка распакованного расширения в настоящий Chrome |
| Автопроверки | Реальный вывод `npm test`, `npm run check`, `npm run test:browser` |
| Docker | Сборка, `--wait`, `/health` и `npm run test:docker`; только текущий том и зависимости |
| Video Download API | Явные `en`/`zh`, честная ошибка без дорожки, нет платного запуска при открытии/смене языка, восстановление ID без дубликата |
| Сохранность | Результаты переживают пересоздание; копия текущего тома восстановлена в отдельный проект |
| Ошибки/перезапуск | Статус задания восстанавливается, SRT и настройки не теряются |
| Расширение | Оформление без плеера, реальный iframe/fullscreen/seek, восстановление после перезапуска Chrome |
| Пиньинь и TTS | Локальный пиньинь и выбранный браузерный голос/скорость работают |
| DeepSeek / OpenAI | Без ключа доступны субтитры; с согласия проверен перевод, ключ не раскрывается странице/логам |
| Платформы | Отдельные прогоны macOS/arm64, Linux/amd64 и Windows PowerShell + Docker Desktop, включая восстановление |

Для каждого прогона фиксируйте commit, ОС/архитектуру, команды и результат. Сетевые платные запросы — только с отдельного согласия. Пока нет доказательств, выпуск остаётся кандидатом.
