# Текущий рабочий режим: локально, без Docker

На текущем Mac используется **нативный сервер через LaunchAgent**. Docker — вариант поставки; для обычных локальных изменений запускать или пересобирать его не нужно. Не запускайте два сервера на одном порту.

## Сервер

- API субтитров: `http://127.0.0.1:43817`.
- LaunchAgent: `com.subsanywhere.local-server`.
- Настройки: `~/Library/LaunchAgents/com.subsanywhere.local-server.plist`.
- Настроен автозапуск при входе и восстановление процесса.
- Существующий Python: `~/.hermes/venvs/video-url-to-subtitles/bin/python`. Для текущего сервера нужен Python 3.11 и только `pypinyin` из Python-зависимостей проекта; старое окружение может содержать неиспользуемые пакеты.
- Лог: `~/Library/Logs/subsanywhere-local-server.log`.

Сервер загружает **только готовые субтитры** через Video Download API и локально добавляет пиньинь. ASR, загрузка аудио, работа с моделями, импорт cookies, автоматический бюджет ресурсов и активная база словаря удалены. Старые переменные этих функций в настройках не включают их обратно. Озвучка в расширении удалена.

Проверка:

```sh
curl --fail http://127.0.0.1:43817/health
launchctl print gui/$(id -u)/com.subsanywhere.local-server
```

Перезапуск после завершения записи/заданий, например после изменения Python-сервера:

```sh
launchctl kickstart -k gui/$(id -u)/com.subsanywhere.local-server
```

После правки plist его нужно выгрузить и загрузить заново; `kickstart` не перечитывает настройки:

```sh
launchctl bootout gui/$(id -u)/com.subsanywhere.local-server
launchctl bootstrap gui/$(id -u) "$HOME/Library/LaunchAgents/com.subsanywhere.local-server.plist"
```

Не запускайте параллельно `npm run local-server`: LaunchAgent обслуживает тот же порт, а настройки по умолчанию могут выбрать другой каталог данных. Изменения исходников не означают, что работающий процесс уже обновлён; здесь перезапуск не подтверждается.

## Данные и резервная копия

Рабочий каталог на текущем Mac:

```text
~/Library/Application Support/SubsAnywhere/data/
  subtitles/       # текущие SRT и состояние заданий; старые файлы не удаляются
    preparations/  # неиспользуемые старые данные подготовки; сервер их не открывает
  words.sqlite3    # неиспользуемый архив; сервер его не открывает
```

Путь задаётся через `SUBSANYWHERE_OUTPUT_DIR` в LaunchAgent. Существующие кэшированные субтитры и старые данные подготовки переводов сохраняются без переноса или удаления; архивирование переводов больше не поддерживается. Отдельное сохранение полученных в браузере субтитров остаётся доступным. Старые аудиофайлы и результаты распознавания, кэши моделей и база словаря сохраняются, но не являются функциями текущего сервера.

Историческая копия переноса из Docker: `~/Library/Application Support/SubsAnywhere/backups/docker-<дата-время>/`; отчёт — `~/Library/Application Support/SubsAnywhere/migration-report.json`. Оригинальные Docker-тома и старый `~/Downloads/SubsAnywhere` сохранены. Архивы cookies, если имеются, также не используются. Не удаляйте их при обновлении и не применяйте `docker compose down -v`/очистку томов.

Нативные изменения **не синхронизируются обратно в Docker**. Для резервирования нативных данных остановите сервис на время копирования рабочего каталога, сохраните отдельно приватный файл ключа и plist с ограниченным доступом. Копия профиля Chrome нужна отдельно. Возвращение к Docker требует намеренного переноса актуальных субтитров; [команды резервирования и восстановления текущего Docker-тома](RELEASE.md#резервная-копия-и-восстановление) не копируют нативный каталог.

## Video Download API

Сервер обращается к `SUBSANYWHERE_VIDEO_API_URL` (по умолчанию `https://p.savenow.to`) без yt-dlp, cookies и чтения профиля Chrome. Пиньинь вычисляется локально.

Ключ: `SUBSANYWHERE_VIDEO_API_KEY` либо приватный файл `SUBSANYWHERE_VIDEO_API_KEY_FILE`. Стандартный путь — `~/Library/Application Support/SubsAnywhere/video-api-key`, вне репозитория. Создайте каталог, затем приватным редактором создайте файл с одним ключом и ограничьте права:

```sh
mkdir -p "$HOME/Library/Application Support/SubsAnywhere"
# После создания файла редактором:
chmod 600 "$HOME/Library/Application Support/SubsAnywhere/video-api-key"
```

Не печатайте ключ в терминале, логах, чате или документации и не добавляйте его в расширение. Нестандартный путь/адрес задавайте в LaunchAgent, не только в интерактивной оболочке. После правки plist примените его указанным выше способом. Для стандартного пути секрет не нужно помещать в plist.

Выберите `en`/`zh` и нажмите **«Скачать»**; открытие окна или смена языка не создают новое платное задание. Китайские субтитры запрашиваются как `zh-Hans`. Оплата возможна уже при принятии задания в очередь. ID сохраняется для проверки после таймаута/перезапуска без повторной отправки; сначала восстановите статус. Старые SRT остаются, новые результаты разделены по языку.

## Проверка изменений

Исторические материалы в `~/Library/Application Support/SubsAnywhere/verification/` относятся к прежней версии, не подтверждают нынешний сервер или удалённые функции. В рамках обновления документации тесты и перезапуск не выполнялись.

Изменения расширения подхватываются через **Reload** в `chrome://extensions` и обновление страницы. Для обновления сервера переустановка или сброс данных расширения не нужны.
